9. GUÍAS DE REFERENCIA
────────────────────────────────────────────────────────────────

  9.1. CÓMO AGREGAR UN ITEM AL MENÚ
  ────────────────────────────────────
  En index.html, dentro de <div class="menu-grid">:

    <article class="menu-card reveal-up" style="--delay: 0.Xs">
      <div class="menu-card__img-wrap">
        <img
          src="assets/images/menu-item-N.jpg"
          alt="[Nombre] — [descripción corta]"
          width="400" height="400" loading="lazy"
        />
        <!-- Opcional: -->
        <div class="menu-card__badge">Favorito</div>
      </div>
      <div class="menu-card__body">
        <h3>[Nombre del ítem]</h3>
        <p>[Descripción]</p>
        <span class="menu-card__price">$[Precio]</span>
      </div>
    </article>

  Para ítem destacado (central): agregar clase menu-card--featured.

  9.2. CÓMO CAMBIAR UN DATO DE CONTACTO
  ────────────────────────────────────────
  Buscar en index.html por "FRONT-007".
  Cambiar en 3 lugares:
    1. <ul class="contact__list"> → dirección, teléfono, whatsapp, horario
    2. <a class="fab-whatsapp" href="https://wa.me/NUMERO"> → FAB flotante
    3. <script type="application/ld+json"> → Schema.org (telephone, streetAddress)

  9.3. CÓMO ACTUALIZAR EL MAPA
  ──────────────────────────────
  En index.html, buscar <iframe en la sección #contacto.
  Reemplazar el src completo con el embed de Google Maps del local real:
    1. Ir a Google Maps → buscar el local
    2. Compartir → Insertar mapa → copiar iframe src
    3. Reemplazar solo el atributo src del iframe existente

  9.4. CHECKLIST DE ENTREGA
  ──────────────────────────

             Cards genéricas sin personalidad.

             Tipografía con carácter (Oswald display + Lora body).

11. CONVENCIONES Y REGLAS ESTRICTAS
────────────────────────────────────────────────────────────────

  11.1. REGLAS ABSOLUTAS
  ──────────────────────
  ✗  NO agregar frameworks (React, Vue, Svelte, etc.)
  ✗  NO agregar librerías JS externas (jQuery, GSAP, etc.)
  ✗  NO usar !important en CSS salvo @media prefers-reduced-motion
  ✗  NO romper las clases .reveal-* (el observer las necesita)
  ✗  NO escribir CSS inline en el HTML
  ✗  NO duplicar estilos ya definidos en :root
  ✗  NO tocar el backend para cambios de UI o contenido
  ✗  NO crear archivos CSS nuevos (todo va en styles.css o animations.css)
  ✗  NO crear archivos JS nuevos (todo va en main.js)

  ✓  BEM estricto: bloque__elemento--modificador
  ✓  Variables CSS: siempre usar las de :root
  ✓  Imágenes: siempre width + height + loading="lazy"
  ✓  Links externos: siempre target="_blank" rel="noopener noreferrer"
  ✓  Secciones: siempre con scroll-margin-top (ya está vía section[id])
  ✓  ARIA: aria-label en elementos interactivos sin texto visible

  11.2. CONVENCIONES DE NAMING
  ──────────────────────────────
  IDs de sección:  #inicio | #nosotros | #menu | #club | #contacto
  IDs únicos JS:   navbar | navMenu | navBurger
  Clases reveal:   .reveal | .reveal-left | .reveal-right | .reveal-up
  Clases estado:   .is-visible | .is-open | .navbar--scrolled

  11.3. ORDEN DE EDICIÓN
  ──────────────────────
  Para cualquier cambio de contenido o datos:
    1. index.html (versión PROD)
    2. descargas/config.js (versión descargable)
    3. descargas/main.js si el campo no estaba inyectado
  Nunca editar solo uno de los tres.
